# ❖ Atlas v0.2 Release Gate Precedence

Authoritative release gating is defined by explicit human approval, not by the presence of green technical checks.

## Gate Layer Definitions

- **Technical check (`PASS`)** — an automated or manual technical gate reports that a specific criterion is satisfied, e.g. schema validation, license scan, checksum verification, or category coverage.  
  `PASS` does not authorize release.
- **Release gate (`BLOCKED` / `UNBLOCKED`)** — the authoritative release-state signal.  
  `BLOCKED` means release cannot proceed. `UNBLOCKED` means release may proceed.
- **Human approval gate** — final, decisive reviewer approval for reviewed Atlas expansion records.  
  This gate has the highest release authority and overrides every automated technical gate.

## Precedence Order

1. Human approval gate
2. Release gate
3. Technical checks / validation reports

## Atlas v0.2 Application

- Any pending, `needs_revision`, or reviewed-but-`rejected` expansion record keeps the release gate `BLOCKED`.
- Automated status fields named `PASS`, `pass`, or equivalent may be true and still coexist with `BLOCKED`. They signal completed technical work, not release authorization.
- Release may proceed only when the human approval gate is explicitly satisfied.

## Exception Rule

There are no exceptions to human approval authority for Atlas v0.2.

## Audit Artifacts

- `metadata/v0.2_review_gate_status.json` — authoritative release gate source for v0.2
- `metadata/releases/v0.2_release_candidate.json` — release candidate metadata
- `docs/v0.2_review_state_audit.md` — current human review completion state
- `docs/v0.2_review_state_reconciliation.md` — review-state reconciliation findings

## Release Invariant

Release remains blocked while:

```text
pending > 0
needs_revision > 0
rejected > 0
```

Release may proceed only when every reviewed expansion record is explicitly approved through the human approval gate.
