## 4. Repair Strategy

### Phase 1 — Provenance Resolution (Blocking)

| Record ID | Action | Verification |
|---|---|---|
| `s5_02_software_engineering_programming_0029` | Add CC-BY-SA-4.0 attribution and share-alike documentation to source registry or record lineage | Confirm attribution fields populated and linked to source_id |

### Phase 2 — Content Revision (6 records)

Each record receives a human-authored content expansion. The revision is recorded in `review/revisions/v0.2/<record_id>.json` using `revision_template.json`.

| Record ID | Expansion Focus | Expected Diff |
|---|---|---|
| `h2_05_hardware_engineering_embedded_systems_0012` | Scheduler semantics, real-time constraints, use-case implications | 2–3 sentences of operational context |
| `b1_07_business_knowledge_finance_0001` | Investment return rationale, rate/inflation sensitivity, horizon dependency | 2–3 sentences of practical reasoning |
| `h4_05_hardware_engineering_embedded_systems_0004` | Scheduling guarantees, real-time constraints, use-case implications | 2–3 sentences of operational context |
| `h3_05_hardware_engineering_firmware_0003` | ROM/EEPROM context, update-role detail, system-context examples | 3–4 sentences of expanded definition |
| `s5_02_software_engineering_programming_0029` | Expanded programming explanation with rationale | 2–3 sentences of additional depth |
| `b2_07_business_knowledge_finance_0002` | Nominal vs real rate, compounding-frequency effects, horizon dependency | 2–3 sentences of practical reasoning |

### Phase 3 — Second Human Review

Every revised record undergoes a second human review by a reviewer different from the original.

| Gate | Criteria |
|---|---|
| Original factual correctness | Revised content contains no errors introduced by expansion |
| Depth adequacy | Content now meets the category-specific depth threshold |
| Provenance cleared | All license/attribution blockers documented (if applicable) |
| Attribution retained | CC-BY-SA/RAIL-M attribution metadata preserved (if applicable) |
| Reviewer separation | Second reviewer is not the original reviewer |

Possible outcomes:
- **Approved** — record moves to `approved` for inclusion
- **Needs further revision** — record returns for a second revision cycle
- **Rejected** — escalated if not salvageable after two cycles
