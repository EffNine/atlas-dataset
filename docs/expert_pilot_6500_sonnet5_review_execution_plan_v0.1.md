# Atlas Expert Pilot Phase 1B — Sonnet 5 Model Review Execution Plan v0.1

## Purpose

Define how the 324-record Phase 1B review sample
(`review/expert_pilot_6500_review_sample_v0.1.jsonl`) is reviewed by an AI
reviewer model (Anthropic Claude Sonnet 5) instead of human reviewers.

This document is an **execution plan only**:

- no review execution happens from this document
- no labels, verdicts, or dimension scores are generated by this document
- no reviewer is assigned to any record by this document
- the review input payloads and prompts are defined here, not run

Execution is a separate, approved step that consumes this plan.

## Relationship to the Human Review Guideline

- `docs/expert_pilot_6500_human_review_guideline_v0.1.md` remains the
  canonical rubric and calibration procedure (dimensions, verdict rules,
  acceptance thresholds, output schema).
- **This plan replaces the human reviewer workflow** with an AI reviewer
  workflow for Phase 1B execution. Rubric, verdict rules, decision schema,
  validation rules, and acceptance math are unchanged.
- **Blind review requirement is preserved**: the reviewer model must never
  see the automated gate's output while scoring.

## Reviewer Model

| Property | Value |
|----------|-------|
| Model | Anthropic Claude Sonnet 5 (API) |
| Reviewer identity (decision file `reviewer` field) | `ai-reviewer:claude-sonnet-5` |
| Temperature | 0 (deterministic scoring) |
| Output | strict JSON per record (schema below) |
| Mode | one record per call; no tools, no external data, no memory across calls |
| Rate limit / retry | 1 call at a time; exponential backoff on 429/5xx; max 3 attempts per record |
| Malformed output | retry once; if still malformed, flag for human adjudication (never auto-fabricate a verdict) |

## Blind Review Requirement

### What the model sees (input payload)

Each review input payload contains ONLY the record's observable content:

- `record_id`, `source_id` (for provenance reference, not as a hint)
- `domain`, `expert_tier`, `difficulty`, `type`
- `license`, `attribution`
- `problem`, `context`, `solution`
- `verification` (method, status, evidence)
- `provenance` (original_id, transformations, ingestion_pipeline)
- `metadata` (language, subdomains, synthetic, model_generated, notes)
- `messages` (user/assistant turns)
- `extraction` (source-specific facts: repo, fail_to_pass_count, problem_source, etc.)

### What the model must NEVER see (blind fields)

- `calibration.auto_gate`
- `calibration.quality_score`
- `calibration.difficulty`/`expert_tier` (when they act as gate hints; they are
  stripped from the payload — the reviewer derives tier/difficulty from content)
- any automated dimension score
- the expected verdict, the acceptance threshold, or any aggregate statistics
  of the cohort

### Why blind

The calibration objective is to compare independent AI judgement against the
automated gate. Showing the gate's verdicts would make agreement a tautology
and defeat the calibration purpose.

## Input Payload Construction

At execution time (not now), a preparation step reads the sample and emits
one blind payload per record:

- `review/expert_pilot_6500_sonnet5_input_v0.1.jsonl`
- one JSON object per line:
  `{"review_id": ..., "record_id": ..., "payload": {<record minus calibration and hints>}}`
- deterministic order (same as sample order)
- payload file must contain no `auto_gate` / `quality_score` values anywhere
  (verified by a grep guard before any model call)

## Review Prompt Template

System instructions (constant for every call):

```
You are an expert data reviewer for the Atlas AI data engineering platform.
You review one expert record at a time against a fixed rubric. You are blind:
you do not see any automated score, gate verdict, or cohort statistics.
Base your scores ONLY on the record content provided.

Rubric (score each dimension 1-5):
- correctness: verifiable correctness of the solution given the problem and evidence
- reasoning_depth: multi-step, complete reasoning; all branches handled
- explanation_quality: clarity, structure, self-containedness
- provenance_confidence: trustworthiness of source/license/original_id/verification evidence

Record-specific checks:
- license must be permissive (MIT, Apache-2.0, CC-BY-4.0, arXiv non-exclusive); else REJECT
- any private key, AWS key, OpenAI key, or credential path in content => REJECT
- provenance fields must be present and non-empty; else lower provenance_confidence

Verdict rules:
- KEEP: correctness >= 3 AND provenance_confidence >= 3 AND license OK AND no security concern
- REVIEW: otherwise, but not REJECT (borderline)
- REJECT: correctness <= 2 OR provenance_confidence <= 1 OR non-permissive license OR security concern

Respond with exactly one JSON object:
{"verdict": "KEEP|REVIEW|REJECT", "dimensions": {"correctness": 1-5,
 "reasoning_depth": 1-5, "explanation_quality": 1-5, "provenance_confidence": 1-5},
 "notes": "concise, specific rationale"}
```

User turn (per record):

```
Review this record:
<blind payload JSON>
```

The model output is stored verbatim in the decision file; `reviewed_at` and
`auto_gate_snapshot` are added by the aggregation step, never by the model.

## Execution Workflow (Step order at run time)

### Step 0 — Preconditions
- [ ] Sample file exists (324 lines) and is checksum-verified
- [ ] Quality report exists (baseline for comparison)
- [ ] Sonnet 5 API credentials available; model name confirmed
- [ ] Blind input payload generation script validated on 3 records

### Step 1 — Prepare blind inputs
- [ ] Generate `review/expert_pilot_6500_sonnet5_input_v0.1.jsonl`
- [ ] Verify payload file contains NO `auto_gate`, `quality_score`, or hint fields
- [ ] Check payload count == 324 and record_ids match the sample 1:1

### Step 2 — Execute review calls
- [ ] One Sonnet 5 call per record, temperature 0
- [ ] Retry policy: backoff on 429/5xx, max 3 attempts
- [ ] Log every call (review_id, status, latency, token usage)
- [ ] Never pass the model any value from the `calibration` block

### Step 3 — Record decisions
- [ ] Write `review/expert_pilot_6500_review_decisions_v0.1.jsonl`
- [ ] Validate: 1 decision per record, no duplicate record_id, JSON schema valid,
      `reviewer == "ai-reviewer:claude-sonnet-5"`, notes non-empty
- [ ] Malformed/flagged records listed separately for human adjudication

### Step 4 — Compute acceptance (unchanged from guideline)
- [ ] Acceptance rate = KEEP ÷ total reviewed
- [ ] ≥ 80% → supports GO; 60–80% → HOLD; < 60% → STOP
- [ ] Agreement vs `auto_gate` computed post-hoc (aggregation only)
- [ ] Disagreements listed by record, stratum, dimension
- [ ] Write `reports/expert_pilot_6500_review_summary_v0.1.json`
- [ ] Append AI-review section to `reports/expert_pilot_6500_decision_v0.1.md`

### Step 5 — Verify
- [ ] Fresh verification of decision file (counts, uniqueness, schema)
- [ ] Confirm no dataset/sample/manifest mutation
- [ ] Confirm blind guard: no prompt or payload contained gate values
- [ ] Report measured results only

## Validation Rules

- Exactly one decision per reviewed record; no duplicate `record_id`.
- No overlap with prior decision batches (append-only semantics if used).
- `reviewer` MUST be `ai-reviewer:claude-sonnet-5` — never a fabricated
  human identity, never `auto-batch` (this is an AI review, not a
  criteria-gated batch approval).
- `notes` concise and specific; no verbatim repetition across records.
- No decision may mutate `review/` sample state, the manifest, the quality
  report, or any dataset artifact.

## Safeguards

- Blind guard is enforced structurally (payload generation + grep guard) and
  at review time (prompt contains no gate values).
- The model gets one record per call — no cohort statistics, no ordering
  context that could bias scoring.
- Any record the model flags as containing sensitive material is double-checked
  by the security hard gate before any verdict is accepted.
- If the model's verdict contradicts the security hard gate, the hard gate wins.

## Constraints

- No training, no release, no dataset modification, no unverified sources.
- Open-Platypus remains HOLD.
- No review execution from this document; no labels generated by this document.
